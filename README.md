# 창시디언 : 옵시디언과 유사한 연결 · AI 지식 그래프 노트 — 모바일/구글 드라이브·로컬 폴더 연동/GitHub 배포판

기존 `knowledge-graph-notes.html`에 여러 기능을 더한 버전입니다. 그래프뷰·검색·AI 질의응답 등
나머지 기능은 그대로입니다.

## 0) 두 가지 실행 방법 중 골라서 쓰면 됩니다

|  | **Yeongyeol.exe** (Windows, 로컬) | **GitHub Pages** (웹, 어디서나) |
|---|---|---|
| 준비물 | 더블클릭 한 번, 끝 | GitHub 계정 + 저장소 |
| 저장 위치 | exe 옆 `notes/` 폴더에 노트 하나당 `.md` 파일 | 브라우저 저장소(이 기기에만) |
| 탐색기로 노트 붙여넣기 | ✅ 가능 | ✅ (아래 "로컬 폴더" 기능으로 가능, 크롬·엣지만) |
| 휴대폰에서 접속 | ❌ | ✅ |
| 구글 드라이브 동기화 | ✅ 가능 | ✅ 가능 |

둘 다 같은 `index.html`을 쓰기 때문에 기능은 동일합니다.

## 0-1) Yeongyeol.exe 사용법

1. `Yeongyeol.exe`를 아무 폴더에나 두고 더블클릭합니다. (윈도우가 "알 수 없는 게시자"
   경고를 띄우면 "추가 정보 → 실행"을 눌러주세요 — 서명되지 않은 개인 배포 파일이라 뜨는
   정상적인 경고입니다.)
2. 검은 콘솔 창이 하나 뜨고, 기본 브라우저로 앱이 자동으로 열립니다. **이 콘솔 창을 닫으면
   앱도 함께 종료됩니다** — 안 쓸 땐 닫지 말고 최소화해두세요.
3. 처음 실행하면 exe 옆에 폴더 두 개가 자동으로 생깁니다.
   - `notes/` — 노트가 `.md` 파일 하나씩 저장되는 곳. **여기에 다른 곳에서 만든 .md
     파일을 그대로 복사해 넣으면**, 앱에서 새로고침(F5)했을 때 노트로 나타납니다.
   - `data/` — 설정, 편집 이력 등 노트 이외의 데이터.
4. 사이드바 아래에 "📁 로컬 폴더에 저장 중" 표시가 뜨면 정상적으로 로컬 저장 모드로
   동작하고 있는 것입니다.

**주의할 점**
- `notes/` 폴더에서 `.md` 파일을 지우면 앱에서도 그 노트가 사라집니다(휴지통을 거치지
  않는 즉시 삭제입니다).
- exe를 옮기고 싶으면 exe와 `notes/`, `data/` 폴더를 함께 옮기면 됩니다.

## 1) 기능

- **구글 드라이브 양방향 동기화**: 노션 대신 구글 드라이브를 씁니다. 브라우저에서 바로
  드라이브 API에 접속하기 때문에(중계 서버 불필요) 설정이 훨씬 간단합니다 — 3장 참고.
- **로컬 폴더 불러오기(웹)**: GitHub Pages로 접속했을 때도 이 기기의 폴더 하나를 지정해
  `.md` 파일로 저장할 수 있습니다(크롬·엣지 데스크톱). 탐색기에서 그 폴더에 파일을
  직접 넣어도 다음 동기화 때 노트로 들어옵니다.
- **그래프뷰에서 노트 미리보기**: 그래프의 노드를 클릭하면 화면 이동 없이 오른쪽에
  노트가 바로 열리고, 클릭한 노드와 **직접 연결된 노드만** 강조되고 나머지는 흐려집니다.
- **Windows 실행 파일(exe)**: 브라우저·GitHub 계정 없이 더블클릭만으로 실행되고, 노트를
  이 기기의 진짜 폴더에 `.md` 파일로 저장합니다 (위 0-1 참고).
- **독립 실행 가능(웹)**: `window.storage`가 없는 환경(GitHub Pages 등)을 자동 감지해
  브라우저 `localStorage`로 대체 저장합니다.
- **모바일 UX 보강**: 좁은 화면에서 사이드바가 햄버거(☰) 버튼으로 열고 닫힙니다.
  PWA로 "홈 화면에 추가"하면 오프라인에서도 앱 껍데기가 열립니다.
- **그래프뷰 클릭/드래그 버그 수정**, 라벨이 항상 다 보이던 것 정리(확대·허브 노드·호버 시에만).
- **관련 노트 연결**: 편집 화면에서 제목 검색으로 다른 노트를 골라 `[[위키링크]]`를 자동 삽입.
- **폴더(범주)**: 노트에 폴더를 지정하고 사이드바에서 폴더별로 필터링.

## 2) 파일 구성

```
index.html                 메인 앱 (이것만 있어도 로컬 저장으로는 동작)
Yeongyeol.exe               Windows용 실행 파일 (index.html이 내장되어 있어 단독 실행 가능)
manifest.webmanifest       PWA 매니페스트 (GitHub Pages용)
service-worker.js          오프라인 캐싱 (GitHub Pages용)
icons/                     앱 아이콘 5종 (GitHub Pages용)
```

exe만 쓸 거라면 `Yeongyeol.exe` 하나만 있으면 되고, GitHub Pages로만 쓸 거라면 exe는
빼고 올려도 됩니다.

## 3) 배포 방법 (GitHub Pages)

### 3-1. GitHub Pages에 올리기

1. GitHub에 새 저장소를 만들고 위 파일 전체(icons 폴더 포함, exe는 제외)를 업로드합니다.
2. 저장소 **Settings → Pages**로 이동해 Source를 "Deploy from a branch", 브랜치는
   `main`, 폴더는 `/(root)`로 지정하고 저장합니다.
3. 몇 분 뒤 `https://<사용자명>.github.io/<저장소명>/` 주소로 접속됩니다.

여기까지만 해도 모바일 반응형 + 오프라인 PWA로 정상 동작합니다. 구글 드라이브 동기화를
쓰려면 아래 3-2를 추가로 진행하세요.

### 3-2. 구글 드라이브 연동 준비 (동기화를 쓸 경우에만 필요)

구글 API는 중계 서버 없이 브라우저에서 바로 접속되지만, **본인 명의의 구글 클라이언트
ID**를 한 번 발급받아야 합니다(구글이 "이 주소에서 온 요청은 허용" 하고 확인하는
용도입니다).

1. [Google Cloud Console](https://console.cloud.google.com/)에서 새 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 "Google Drive API"를 검색해 사용 설정합니다.
3. **API 및 서비스 → OAuth 동의 화면**에서 User Type을 "외부"로 만들고(개인 사용은
   이걸로 충분), 앱 이름 등 기본 정보만 채운 뒤 "테스트 사용자"에 본인 구글 계정을
   추가합니다 — 이렇게 하면 구글의 별도 앱 심사 없이 바로 쓸 수 있습니다.
4. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**를
   선택하고, 애플리케이션 유형은 "웹 애플리케이션"으로 지정합니다.
5. "승인된 자바스크립트 원본"에 실제 접속 주소를 추가합니다 — 예:
   `https://<사용자명>.github.io` (GitHub Pages), 로컬 테스트 시 `http://localhost:PORT`도
   추가할 수 있습니다. **경로 없이 도메인까지만** 적어야 합니다.
6. 만들어진 **클라이언트 ID**(`xxxxxxxx.apps.googleusercontent.com` 형식)를 복사해둡니다.

### 3-3. 앱에서 연결

앱 → ⚙ 설정 → 구글 드라이브 연동에서 클라이언트 ID와 (원하면) 폴더 이름을 입력하고
**"구글 드라이브에 연결 / 지금 동기화"**를 누릅니다. 처음엔 구글 로그인 창이 뜨고,
권한을 승인하면 지정한 이름의 폴더(기본값 "연결 노트")가 내 드라이브에 만들어지고
그 안에 노트가 `.md` 파일로 올라갑니다.

### 3-4. 로컬 폴더 (선택)

앱 → ⚙ 설정 → 로컬 폴더에서 **"폴더 선택"**을 누르고 이 기기의 폴더를 하나 고른 뒤
**"지금 동기화"**를 누릅니다. 크롬·엣지 데스크톱에서만 지원되는 기능입니다(사파리·
파이어폭스·모바일 브라우저는 미지원). 한 번 선택해두면 다음에 열 때도 기억하지만,
브라우저 정책상 처음 한 번은 버튼을 눌러 권한을 다시 확인해야 할 수 있습니다.

## 4) 동기화 동작 방식과 한계 (구글 드라이브 · 로컬 폴더 공통)

- 노트마다 언제 마지막으로 양쪽이 일치했는지를 기준으로, 그 이후 이 기기에서만
  바뀌었으면 원격(드라이브/폴더)에 반영하고, 원격에서만 바뀌었으면 이 기기에 반영합니다.
  **양쪽 다 바뀐 경우**엔 원격 쪽 내용을 "(충돌 사본)"이라는 새 노트로 따로 보관하고,
  이 기기 내용을 원격에 반영합니다.
- 제목·본문·태그·폴더가 동기화됩니다. `.md` 파일 형식은 ZIP 내보내기와 동일한
  프런트매터(`id/title/tags/folder/created/updated`)를 씁니다 — 그래서 두 방식을
  섞어 써도(예: 내보낸 zip을 로컬 폴더에 풀어넣기) 대부분 그대로 인식됩니다.
- **삭제는 동기화하지 않습니다.** 휴지통으로 보낸 노트나 원격에서 지운 파일은
  건드리지 않습니다 — 실수로 대량 삭제가 전파되는 걸 막기 위한 의도적인 제약입니다.
- 구글 액세스 토큰은 메모리에만 잠깐(약 1시간) 보관되고 저장소에 남지 않습니다 —
  브라우저를 새로고침하면 다시 로그인해야 합니다.

## 5) 참고: 왜 "아이폰/안드로이드 기본 메모 앱"과는 직접 연동하지 않았는가

iOS·Android 기본 메모 앱은 제3자 웹앱이 쓸 수 있는 공개 API가 없습니다. 브라우저에서
할 수 있는 최선은 "공유하기(Share Sheet)"로 텍스트를 한 방향으로 내보내는 정도이며,
지금 구현한 구글 드라이브 연동처럼 양방향 실시간 동기화는 기술적으로 불가능합니다.



# 옵시디언 구글 드라이브 연동 오류 해결 가이드 (README)

본 문서는 깃허브 페이지(`semyo0513.github.io`)에서 옵시디언(Obsidian)을 구글 드라이브와 연동할 때 발생하는 로그인 인증 오류(`401 invalid_client`, `403 access_denied`)의 원인과 해결 방법을 순서대로 정리한 가이드입니다.

---

## 🚨 1단계: `401 invalid_client` / `no registered origin` 오류 해결

**원인:** 
구글 클라우드 콘솔에서 발급한 OAuth 클라이언트 ID의 '애플리케이션 유형'이 잘못 설정(데스크톱)되어, 웹사이트 주소(URL)를 로그인 요청이 허용된 '승인된 원본'으로 등록하지 못했기 때문에 발생합니다.

**해결 방법: '웹 애플리케이션' 유형으로 클라이언트 ID 새로 만들기**
1. [Google Cloud Console](https://console.cloud.google.com/)에 접속하여 로그인합니다.
2. 상단 돋보기 검색창(🔍)에 **`사용자 인증 정보`**(Credentials)를 검색하여 이동합니다.
3. 화면 상단의 `[+ 사용자 인증 정보 만들기] -> [OAuth 클라이언트 ID]`를 클릭합니다.
4. **애플리케이션 유형**을 반드시 **`웹 애플리케이션(Web application)`**으로 선택합니다.
5. 화면 하단의 **승인된 자바스크립트 원본** 항목에서 `[URI 추가]`를 누르고 아래 주소를 입력합니다:
   - 입력할 주소: `https://semyo0513.github.io` (※ 끝에 `/` 기호가 들어가지 않도록 주의)
6. `[만들기]` 버튼을 누르고 새로 생성된 긴 클라이언트 ID를 복사합니다.
7. 옵시디언 연동 설정 화면으로 돌아가 기존 ID를 지우고 새 클라이언트 ID를 붙여넣습니다. (구글 서버 반영까지 약 5분 소요)

---

## 🚨 2단계: `403 access_denied` (테스트 중인 앱) 오류 해결

**원인:** 
구글 클라우드 프로젝트의 OAuth 앱 상태가 '테스트 중(Testing)'이어서, 개발자가 미리 허용해 둔 사용자(테스트 사용자)가 아니면 접근을 차단하기 때문에 발생합니다.

**해결 방법: 테스트 사용자(Test Users) 목록에 본인 계정 추가하기**
1. [Google Cloud Console](https://console.cloud.google.com/)에 접속합니다.
2. 상단 돋보기 검색창(🔍)에 **`OAuth 동의 화면`**(OAuth consent screen)을 검색하여 클릭합니다.
3. 이동한 화면에서 스크롤을 맨 아래로 내려 **`테스트 사용자 (Test users)`** 항목을 찾습니다.
4. `[+ ADD USERS (사용자 추가)]` 버튼을 클릭합니다.
5. 연동(로그인)에 사용할 본인의 구글 이메일 주소(예: `semyo0514@gmail.com`)를 정확히 입력하고 저장합니다.
6. 다시 깃허브 페이지로 돌아가서 구글 드라이브 연동을 시도하면 정상적으로 권한 승인이 진행됩니다.

---
**💡 요약 팁:** 
모바일 환경의 구글 클라우드 콘솔은 메뉴 구조가 복잡하게 숨겨져 있고 화면이 잘릴 수 있어 설정이 까다롭습니다. 메뉴 탐색이 어렵거나 페이지 접속이 잘 안 된다면 **컴퓨터(PC) 브라우저를 이용해 설정하시는 것을 강력히 권장**합니다. PC 환경에서는 왼쪽 메뉴에서 `[API 및 서비스] -> [OAuth 동의 화면]` 등을 직관적으로 바로 찾을 수 있습니다.
